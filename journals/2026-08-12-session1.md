## 5. Roadblocks, Failure Modes & Debugging Log

**The AppleDouble bug.** The Day 0 step 0 cell halted:

```
AssertionError: HALT: /content/rml_data/RML_RAW_PROCESSED_Face holds 1441 entries, expected 720 utterance folders.
```

`RML_audio16k_all720.tar` was packed on macOS, so alongside its 1441 real members it carries 1441 AppleDouble sidecars, `._.`, `./._<id>` for every folder, and `./<id>/._audio_16000.wav` for every clip. These hold HFS metadata and nothing else.

The reason nobody caught this when the archive was built: macOS `tar -tf` folds the sidecars back into their parent entries and never lists them. I listed the archive on my Mac and saw 1441 members with no `._` entries, which sent me chasing an ID-mismatch hypothesis for a while. Re-listing the same file with Python's `tarfile` showed 2882 members, 1441 of them AppleDouble, at depths 0/1/2 in a 1/720/720 split. Python's `tarfile` on Linux materializes each one as a real file, so 721 junk entries landed at the top of `MAIN_FOLDER` and 720 more landed one per utterance folder.

This was introduced by the recovery itself. The 16 kHz tar had never been extracted on Linux before today, because on 2026-08-11 the overlay reached the runtime through a live rebind rather than through this cell.

I patched the Day 0 step 0 cell in two places: a sweep that removes any `._*` left in `MAIN_FOLDER` or one level below it by an earlier run of the cell, and a filtered `extractall` that drops AppleDouble members before writing, with an assert that exactly 1441 real members remain. The frame loader counts `image_*.jpg` directly (`docs/recovered/2026-08-11-session1-audio-rebind.py:49`), so these files could never have shifted a frame index, but they do break the folder-count assert on every re-run, which is a real halt on a perfectly good extraction.

A throwaway diagnostic cell confirmed the fix in the runtime:

```
entries 720 | dirs 720 | files 0
sample dirs  ['s1_an1', 's1_an2', 's1_an3'] ['s8_f3chi_su1', 's8_f3chi_su2', 's8_f3chi_su3']
sample files []
16k wavs 720
```

I deleted that cell after the run, since it is scratch and does not belong in a paper-facing notebook. The execution counts now read 1, 2, 3, 5, 6, …, 18, the gap at 4 is that deletion. I left the gap rather than renumbering, because renumbering would misrepresent the run record.

One consequence to note for anyone re-reading the stored outputs: they come from a warm re-run, so the Day 0 step 0 cell printed "Reusing existing extraction" and "Removed 1441 AppleDouble sidecar files left by a previous run." Neither line appears on a cold runtime. The patch is correct on both paths, the `DeprecationWarning` raised at `tf.extractall(MAIN_FOLDER, members=_members)` shows the filtered extract ran, and "16 kHz audio overlaid: 720 files, all 16000 Hz" shows the result landed.

**Manifest drift, benign.** The data-integrity gate reported that all 720 folders hold one more file than `docs/rml_archive_manifest.json` records, e.g. `s7_f1eng_sa5` at 164 rather than 163. That extra file is `audio_16000.wav`, which the overlay puts there on purpose. The path check and the frame-count check both passed. The manifest predates the overlay; it is the manifest that is stale, not the corpus.

## 6. Interpretability Retrospective

The recovery commit left two questions open. One of them is now closed outright, and the other has a better answer than the one I was reaching for.

Closed: `results/` is reproducible from committed code. The notebook contains both the 16 kHz overlay and the rebind, and running it from `82f1886` reaches 76.39% / 79.86%.

The other question, which audio route was actually bound in the runtime when Weeks 1–4 produced the committed `results/`, I nearly answered with the byte-identity of the artifacts, and that argument does not work. Weeks 1–4 read from the cached activations rather than re-extracting them, and `CACHE_PROVENANCE` stamps the cache version, both checkpoint hashes, the meta path, the split sizes and the split-ID hashes, but carries no field describing the audio route. Byte-identity given a reused cache demonstrates determinism, not provenance.

What does settle it is the Day 0 step 2 cross-check inside the Days 1–2 cell. The cached `a_cls` matches the SHAP pickle's `test_feature[:, 1088:1152]` at Pearson r = 1.000000, max|diff| 8.10e-03 base and 7.65e-03 fine-tuned. That pickle came from the upstream training-era run, a different GPU, a different torch build, a different batch size, so the correlation ties the cache to training-era audio and to nothing else. The 44100 Hz route scores 56.94%; activations built on it could not correlate at 1.000000 with training-era features. Today's outputs are then numerically the same as the committed ones, so the cache behind `results/` is that same cache. The committed results rest on training-era 16 kHz audio.

The honest residual is narrow: this does not prove the rebind was textually present in the notebook during sessions 2 and 3. It proves the numbers do not depend on that question. Measurement settles what code archaeology could not, which is the right outcome given that the commits carrying the answer were destroyed.

On the science, both Week 3 results reproduced exactly, and both are negative.

Transfer is at chance. `R_exceeds_null` is False for all six classes. Fear's R = 4.34 is the number that would have made a nice figure, and the random-subset null for fear is 4.01, nearly all of it. The reason is now easy to state: the fine-tuned model is simply more damageable through its audio channel than the base model is, across the board, so *any* k=5 subset produces a ratio above 1. Reading R > 1 as evidence that fine-tuning preserved a specific set of neurons was reading a property of the model pair as a property of the selection. ADR 0006 withdrew the substrate bands for the same reason: both `CONTEXT.md` and ADR 0001 band only R ≤ 1 and collapse everything above 1 into "preservation", which is the region every class occupies.

The Day 13b result is the sharper one, and it constrains how the top-5 selection can be described in the paper. The L1 probe's highest-|weight| neurons do less damage than the measured top-5 in all 12 pairs, as little as 16% of it, and the rank correlation over the top-16 union is negative in 11 of 12. Probe weight magnitude does not rank causal importance in this layer, and it mildly anti-ranks it. This is not surprising in hindsight: an L1 probe finds a sparse set sufficient to *read out* the class from the activation, and mean-ablating a neuron asks what the downstream classifier loses when that coordinate is pinned. A coordinate can be highly readable and easily compensated. But it does mean the Week 2 selectivity result validates the causal effect of the protocol's stated selection rule, not of the causally strongest neurons, and every place the top-5 selection is described has to say so.

What survives as a positive claim is narrower than the original plan and scoped to RML alone: ablating five probe-selected audio dimensions produces a class-selective drop in the true-class probability, with CIs excluding zero on every target class and selectivity ratios up to 10.7. That is real causal validation of modality competition in the audio branch. It is not a mechanism story about what fine-tuning did.

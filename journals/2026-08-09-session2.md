### 4. Empirical Findings & Data Links

**The dominant modality is audio, and it is not close.**

| Model | View | text | video | audio | rank-1 |
| :--- | :--- | ---: | ---: | ---: | :--- |
| base | aggregate `sum(\|φ\|)` | 0.258486 | 0.010561 | 0.084228 | text |
| base | per-neuron `mean(\|φ\|)` | 0.000252 | 0.000165 | 0.001316 | **audio, 5.2×** |
| fine-tuned | aggregate `sum(\|φ\|)` | 0.265253 | 0.006042 | 0.114995 | text |
| fine-tuned | per-neuron `mean(\|φ\|)` | 0.000259 | 0.000094 | 0.001797 | **audio, 6.9×** |

Audio is rank-1 per neuron for all six classes in both models, without exception. The two rows are not competing metrics, `mean(|φ|)` is `sum(|φ|)` divided by the dimension count, so text leads on total mass only because it has 1024 dimensions against audio's 64. ADR 0004 Decision 5's "near-tie resolved by a dimension-invariant tie-break" is wrong on the data, and the truth is a stronger claim than the one it was making. Written up in `docs/adr/0005-day0-dominant-modality-recompute-and-protocol-alignment.md`; the notebook now recomputes this at Day 0 step 2 rather than inheriting it, and saves `results/day0_dominant_modality.json`.

**The SHAP feature space is the ablation space.** `test_feature` in both pickles is `(144, 1152)` = `[text_cls 1024 | v_cls 64 | a_cls 64]`. Columns 1088 onward are the exact tensor this experiment ablates, so Day 0's attribution and Week 2's intervention live in one representation. Week 1 now asserts that this block correlates at r > 0.99 with the freshly extracted test activations, which upgrades the pickles' provenance from "the filename says 0.6724" to a measurement.

**Data is complete and the `- 2` in the frame sampler is explained.** Zero folders missing, zero missing `audio.wav`, zero missing frame paths, zero folders sampling zero frames, no duplicate or blank split IDs, all 720 IDs present in the canonical meta, all labels valid one-hot, exactly 120 samples per class overall and 24 per class in the test split. Every folder carries **both** `audio.wav` and `audio_16000.wav`, which is precisely why `nums = len(files) - 2` yields the true image count. Nobody had written that down, and it is load-bearing: a single stray `.DS_Store` in an utterance folder shifts `nums` by one and silently changes which frames the model sees. This repository lives in `My Drive` on macOS, so that is not hypothetical. Manifest of per-folder counts saved to `docs/rml_file_manifest.json`.

**The fidelity-gate targets are confirmed from primary sources, now in-repo.** `docs/provenance/RML_origin_training_log.txt` ends with `Test (29) 0.763889`; the fine-tune log ends with `Test (15) 0.798611`. Both logs' first lines are the training command lines, which confirm every architecture argument in `MODEL_ARGS` and also record `# Train samples = 518 / # Valid samples = 58 / # Test samples = 144` and the three split filenames the notebook reads. The origin run used `-lr=1e-5 -wd=1e-3 --early-stop=6`, not the `-lr=5e-5 --early-stop=40` a notebook comment claimed, the comment had quoted the fine-tune line for both. Optimizer settings do not matter at inference, so this was a documentation gap, never a behavior bug, and the comment now says that.

**The fast path is exact.** With `mod='tav'`, `MME2E.forward` ends in `weighted_fusion(stack([t_out(t_cls), v_out(v_cls), a_out(a_cls)], -1)).squeeze(-1)` with `weighted_fusion = nn.Linear(3, 1, bias=False)`. Mean ablation touches only `a_cls`, so caching `(t_logits, v_logits, a_cls)` determines the output under any audio ablation. My synthetic check gave `max |reference - fast| = 0.0` and identical argmax, both with and without ablation. Weeks 2–3 run over 100 evaluations; on the slow path each re-reads 144 wav files and roughly 1,300 JPEGs across the Colab Drive mount, about 150,000 file reads in total. GPU time was never the constraint, the original training log shows test evaluation at ~9 it/s, so this removes the part of the run most likely to die. The notebook still proves it at runtime against three real hooked forward passes and falls back to real forward passes if any check disagrees.

**Hook chaining behaves as the falsification check assumes.** Registering the ablation hook first and a capture hook second, the capture hook receives the already-clamped tensor: all five rows of my test came back identical and equal to the module's returned output. That is what makes the new mechanical check possible, under a full 64-dimension clamp every sample must end up with the same `a_cls`, which proves the hook wrote through without depending on any accuracy threshold.

### 6. Interpretability Retrospective

The dominant-modality recompute is the finding I did not expect to get from a pre-flight session. Audio carrying 5–7× text's attribution *per neuron* while text carries three times audio's *total* mass is not a contradiction to be resolved, it is what modality competition looks like when one branch has sixteen times the width of another. The thesis already said "the dominant modality is text and audio" for RML, and this is the mechanical account of why that sentence had to name two. Audio's 64 dimensions are individually the most load-bearing units in the model; text's 1024 dimensions collectively carry more but each one matters less. For an experiment whose intervention is per-neuron, that settles which branch to hook, and it settles it more firmly than ADR 0001's tie-break language ever did.

There is also a pattern in the four notebook bugs worth naming, because it is the same pattern as the v1/v2 failure one level down. Every one of them was a check that *looked* like a gate but could pass while being wrong: a restart that printed instead of restarting, a count assert that would fire too late to help, a buffer tolerance that only worked in the direction someone happened to test, a frame sampler that reads file *counts* rather than file *names*. ADR 0004's lesson was "a fidelity check that can be satisfied by search is not a fidelity check." The version of that lesson I take from today is narrower and more useful: a check that cannot fail loudly at the moment the thing goes wrong is not a check, it is a comment. The Day 0 frame-path gate exists because `sample_imgs_by_interval` will happily hand back a different frame set than training used and raise nothing at all.
